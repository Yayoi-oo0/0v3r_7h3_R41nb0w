# 遮眼子トラッカー（方式 B・現在は予備）

> **現在の本番は方式 A（MediaPipe Unity Plugin）です。**
> Unity 内で完結する `MediaPipeEyeCoverSource` が同じ判定を行っており、
> シーンはそちらを使っています。この Python 版は、
> プラグインで問題が出たときに切り戻すための実装として残しています。
>
> 切り戻す手順：`GameSystems` から `MediaPipeEyeCoverSource` を外し、
> `UdpEyeCoverSource` と `EyeTrackerLauncher` を付けて、
> `EyeCoverInput.sourceBehaviour` に `UdpEyeCoverSource` を指す。

黒い遮眼子に貼った**蛍光ピンクの丸マーカー**を Webカメラで追い、
「マーカーが目の位置にあるか」を判定して Unity へ UDP で送ります。

- **MediaPipe Face Landmarker**（Tasks API） … 左右の目の座標を取るだけ
- **OpenCV (HSV)** … ピンクの丸マーカーそのものを検出
- **判定** … マーカーの重心が、いずれかの目から「両目間隔 × `eye_radius`」以内にあるか

顔のランドマークから遮蔽を推定するより、眼鏡・照明・顔の向きに強く、
どちらの目を覆ったかも分かります。

## 通常の使い方：Unity の再生ボタンだけ

シーンの `EyeTrackerLauncher` が、再生と同時にこのトラッカーを起動し、
再生を止めると停止します。**ターミナル操作は要りません。**

- 既にトラッカーが動いていれば二重起動せず、それを使います
- Unity が異常終了しても、`--parent-pid` の監視で自動的に終了します
- 起動に失敗しても `SPACE` キーで代用でき、画面上部に警告が出ます
- 動かないときは Unity のメニュー **「0v3r 7h3 R41nb0w / 遮眼子トラッカーの環境を準備」**
  （`.venv` を作って依存を入れる。数分かかります）

> macOS の初回は、カメラ使用許可のダイアログが **Unity に対して** 出ます。許可してください。

以下は、キャリブレーションや切り分けのために手で起動する場合の手順です。

## セットアップ（手動起動する場合）

Python 3.9 以上（3.10〜3.12 推奨）が必要です。

初回起動時、MediaPipe の顔ランドマークモデル `face_landmarker.task`（約3MB）を
`models/` に自動ダウンロードします。ネットに繋がる状態で一度起動しておいてください。

```bash
# macOS
./run.command
# Windows
run.bat
```

初回だけ `.venv` を作って依存を入れます（数分）。2回目以降はそのまま起動します。

手動で入れる場合:

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
./.venv/bin/python eye_tracker.py
```

> macOS は初回起動時にカメラ使用許可を聞かれます。
> ターミナルから起動した場合、許可を出すのは「ターミナル」に対してです。

## キャリブレーション（体験会の設営時に1回）

プレビューウィンドウを見ながら:

1. 遮眼子をカメラに向けて **`c`** を押す → 一番鮮やかな色にマーカー色が合う
2. 右下の白黒マスクに**マーカーだけ**が白く出るまで `sat min` / `val min` を上げる
3. 遮眼子を目に当てて、左上が `COVERED L`（または `R`）になるのを確認
4. 目から離したときに `open` に戻るのを確認。戻りが渋ければ `eye r x100` を下げる
5. **`s`** で `calib.json` に保存（次回以降は自動で読み込まれます）

| トラックバー | 意味 |
|---|---|
| `hue` / `hue tol` | マーカーの色相と許容幅 |
| `sat min` / `val min` | 彩度・明度の下限。上げるほど誤検出が減る |
| `eye r x100` | 目までの許容距離（両目間隔に対する％） |
| `circ x100` | 円形度の下限。丸くないピンクを弾く |

## 本番

ゲーム本体を起動するだけです（トラッカーは自動で起動・停止します）。
Unity 側は `F1` でトラッカーの状態（受信レート／顔検出／面積／距離）を確認できます。
トラッカーが未接続のときは画面上部に警告が出て、`SPACE` キーで代用できます。

## オプション

| オプション | 既定 | 説明 |
|---|---|---|
| `--camera N` | 0 | カメラ番号。`--list-cameras` で確認 |
| `--port N` | 51234 | Unity の `UdpEyeCoverSource` と合わせる |
| `--host` | 127.0.0.1 | 別 PC に送る場合に指定 |
| `--no-preview` | — | ウィンドウを出さない（本番） |
| `--hold-frames N` | 10 | 顔を見失った直後、最後の目の位置を使い続けるフレーム数 |
| `--model PATH` | `models/face_landmarker.task` | モデルの場所。手動で置いた場合に指定 |

## 送信するパケット

UDP / JSON / 1フレーム1通:

```json
{"seq": 123, "face": 1, "covered": 1, "eye": "L", "ratio": 0.0121, "dist": 0.34}
```

| キー | 意味 |
|---|---|
| `face` | 顔を検出できているか。0 なら Unity 側は Lost（＝安全側で遮眼子なし） |
| `covered` | マーカーが目の位置にあるか |
| `eye` | `"L"` / `"R"` / `""` |
| `ratio` | マーカーが画面に占める面積比 |
| `dist` | 目までの距離（両目間隔に対する比）。未検出なら -1 |

平滑化はしていません。チャタリング防止は Unity の `EyeCoverInput`
（連続 N フレーム一致＋ヒステリシス）が担当します。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| `NO FACE` のまま | 逆光になっていないか。カメラを目線の高さに |
| マーカーを拾わない | `c` で色を取り直す。`sat min` を下げる |
| 何もないのに `COVERED` | `sat min` / `circ x100` を上げる。背景のピンク色を片付ける |
| 当てても反応が鈍い | `eye r x100` を上げる。Unity 側の `framesToCover` を下げる |
| Unity に届かない | ポート番号の一致を確認。ファイアウォールで Unity の受信を許可 |
| 再生しても起動しない | Unity の Console に `[EyeTrackerLauncher]` のログが出ます。python が見つからない場合はメニュー「遮眼子トラッカーの環境を準備」を実行 |
| モデルのダウンロードに失敗 | README 冒頭の URL を手動で取得し `models/face_landmarker.task` に置く |
